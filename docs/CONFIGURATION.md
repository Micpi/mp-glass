# Configuration

Le panneau **MP Nexus Studio** est accessible aux administrateurs dans la barre latérale Home Assistant et depuis **Info → Personnaliser** sur le dashboard. La page **Info** est accessible à tous : elle affiche les versions de MP Nexus, de l’interface et de Home Assistant, un résumé de l’installation et des conseils d’utilisation. Le bouton **Personnaliser** y apparaît uniquement pour les administrateurs.

Le Studio a deux profondeurs ([ADR 0006](adr/0006-one-path-two-depths.md)). Le **mode essentiel**, par défaut, tient en trois étapes : Analyser, Pièces, Style ; le plan 3D y est présenté comme option. Le **mode expert**, activé par le bouton de la barre supérieure et mémorisé par utilisateur et navigateur, révèle toutes les sections : identité, presets, les deux accents, la teinte et la transparence du verre, les bordures, les ombres, la typographie, le fond, la grille, les espacements, les dimensions, les icônes, les contrôles visibles, le contenu, l'ordre de navigation, les équipements et le plan 3D. Tout se règle sans YAML. Une image Home Assistant peut être utilisée avec une URL locale `/local/...` ou `/api/image/...`. L'aperçu reste visible et réagit avant la sauvegarde ; le bouton ↶ annule la dernière modification non enregistrée.

La navigation du projet crée des destinations réelles et stables : `home`, `lights`, `rooms`, puis une page `area-<id>` par pièce utile et `inventory` s'il reste des entités sans carte spécialisée. Le Studio permet d'afficher, masquer et ordonner les trois destinations principales. On navigue depuis l'en-tête MP Nexus : toutes les vues sauf `home` sont des sous-vues Home Assistant, qui n'affiche donc pas sa barre d'onglets de vues. Sur toutes les vues MP Nexus, la barre supérieure de Home Assistant est masquée, même si un thème la colore ; seules restent ses actions (recherche, Assist, modification) et, sur téléphone, le bouton du menu latéral : ni bandeau, ni flèche retour, ni titre de sous-vue. En mode édition, elle reprend son aspect habituel. L'inventaire s'ouvre depuis une tuile de la page Pièces.

La section Équipements (et l'étape Pièces du mode essentiel) analyse les registries Home Assistant, liste les équipements **sans pièce** (lumières, et équipements du plan) et permet d'affecter une pièce, renommer ou masquer un équipement, un par un ou pour une sélection (« Tout sélectionner », filtre par type et recherche au-delà de trois équipements, « Pièce pour la sélection », « Masquer la sélection »). « Pourquoi cette carte ? » explique chaque décision en une phrase ; les codes bruts restent sous « Données techniques ». La pièce choisie vaut pour tout MP Nexus : page de la pièce et pièce du plan 3D reliée à la même pièce Home Assistant. Depuis 0.7.0, le plan 3D permet aussi de relier ses pièces automatiquement et d'y déplacer, ajouter ou masquer des équipements ([MP Spatial](FLOORPLAN.md#associer-les-pièces-et-les-équipements)). Enregistrer valide le schéma côté serveur. Seuls les administrateurs peuvent écrire.

Le JSON Schema `shared/project.schema.json` est normatif. La copie Python est produite par le build. Le [contrat projet](../PROJECT_CONFIG.md) détaille l'apparence, les rôles et les overrides. En mode expert, **Exporter** télécharge le projet et **Importer** le remplace par un fichier exporté (un projet de schéma 1 est migré) : un résumé dit ce qui change (nom, réglages d'apparence, navigation, équipements, plan 3D, rôles) avant d'enregistrer. L'éditeur graphique de rôles et les modèles réutilisables ne sont pas encore livrés.

Une sauvegarde concurrente n'écrase rien en silence : le Studio indique ce qui a été modifié ailleurs depuis l'ouverture de la page et propose **Reprendre la version enregistrée** ou **Conserver mes modifications**. Rescan et génération lisent les overrides existants. La sortie Lovelace générée n'est jamais la source de configuration.
